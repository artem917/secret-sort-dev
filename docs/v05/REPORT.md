`W_q(S)` — существование прямой победной последовательности с q резервными ячейками, **без Undo**. `R_min` — минимальное q. В настоящей игре Undo остаётся доступен. Плохая ветвь LOSE может быть исправлена отменой; это не объявление необратимого проигрыша пользователя.

Каждый JSON содержит исходные 108 фишек с ID и флагами, seed/ID, версию алгоритма, полную последовательность, SHA-256, нижнюю границу, независимый расчёт свободной ёмкости и метрики. Начальные высоты строго `[10,11,11,11,11,11,11,11,11,10]`, все фишки закрыты, каждый из 9 видов встречается 12 раз. Поле имеет 120 позиций, из них 12 свободны. Положительный trace повторяется `applyAction` с проверкой инвентаря после каждого действия до настоящего `isVictory`.

Это метрики конкретных корректных путей, **не кратчайших решений и не доказательство сложности для человека**. Число использованных слотов само по себе не устанавливает R_min: нижняя граница доказывается отдельно.

## Доказательство нижней границы

В двух колонках высоты 11 находятся начальные группы одного вида A длиной `a=k+1` и `b=11−k`. Они содержат все 12 фишек A. Остальные восемь верхних видов различны, ни один не равен A; их физические начальные группы имеют длину не меньше k. Для k=1..4 пары длин: 2/10, 3/9, 4/8, 5/7.

Рассмотрим **первое** раскрытие фиксированного нижнего слоя либо опустошение колонки. До него новых портов для видов нет: у каждого не-A вида только своя колонка и резерв. Чтобы полностью убрать его начальную группу длины d, надо разместить d фишек в резерве, следовательно q≥d≥k.

Чтобы освободить короткую A-колонку, все 12 фишек A должны поместиться в другой A-колонке над её фиксированным хвостом и в резерве. Другая колонка вмещает не больше `12−(11−b)=b+1` таких фишек. Поэтому `12≤b+1+q`, откуда **q≥k**. Для обратного направления получается `q≥10−k≥k`. Входящие одинаковые фишки могут заменять исходные ID, но не меняют этот баланс общей массы A над неподвижными хвостами.

При q=k−1 ни одно первое освобождение невозможно. Бесплатное раскрытие верхней фишки, частичные пачки, переносы между резервными ячейками и циклы не меняют ёмкости или доступные виды. Начальная позиция не является победой и не может достичь её без такого освобождения. Следовательно W_(k−1)=LOSE. При меньшем q решение также невозможно по монотонности ёмкости. Отдельный проверенный WIN при k завершает доказательство R_min=k.

`generator/barrier.ts` проверяет сертификат, пересчитывая реальные префиксы, высоты, 9×12, все ID, уникальность портов и обе оценки ёмкости. Он не доверяет заявленным числам и не объявляет WIN. `tests/support/v05-independent-proof.mjs` независимо выводит границу **из самой доски**, не читая утверждения production-сертификата. `classifyMinimum` объединяет два разных доказательства только после проверки обоих.

Повреждения схемы, собственных полей, k/q, ёмкости, высот, привязки порядка, портов, префиксов, инвентаря и trace отвергаются. В штатных тестах — 76 отрицательных проверок нижнего доказательства плюс независимые повреждения/reseal сохранений и положительного trace. Исследовательский независимый аудит проверил 151 раскладку двумя движками и тысячи дополнительных мутаций; основная воспроизводимая приёмка остаётся в репозиторных тестах и `scripts/certify-v05.mjs`.

Общий графовый solver также работает при q=0,1,2,3,4: WIN требует действительного trace, LOSE — полного замкнутого множества непобедных состояний, исчерпанный бюджет даёт UNKNOWN. Аналитический сертификат — отдельный способ доказать LOSE. Для нижних ёмкостей 1..3 ограниченный поиск может вернуть UNKNOWN; этот результат **не переименовывается** в LOSE. `solveCertified` принимает математическое доказательство отдельным аргументом и проверяет его независимо от лимита поиска.

## Разнообразие

В обычном генераторе **64 смешанные структуры: по 16 каждого класса**. В каждой 8 смешанных колонок и хотя бы одна колонка содержит 3 вида. Это не четыре готовых поля с заменой цветов.

Основа — две зависимые цепочки, распределяющие дефицит десяти свободных мест. Перестановка порядков дефицитов 1/2 даёт ещё **87 проверенных конструктивных структур**: 21/22/22/22 для классов 1/2/3/4. Затем изменения закрытых хвостов добавляют зависимости между видами. В обычный набор допускаются только изменения, сохранившие проверяемый барьер и имеющие реальный выигрышный trace. Неудача поиска обозначается UNKNOWN и не служит доказательством нерешаемости. Всего код и аудит покрывают **151 различную структуру**; обычный UI выбирает из более смешанного набора 64.

Различие подтверждено инвариантом: матрицы совпадений видов по позициям плюс 12 раундов уточнения связей видов и колонок. Он не меняется при переименовании видов, смене ID одинаковых фишек и перестановке колонок. Разные полные строки доказывают структурное различие; совпадение само по себе не доказывает изоморфизм. SHA не используется как замена этому аргументу. [Все измерения](evidence.json).

Обычный seed выбирает структуру, затем перестановки видов и колонок одинаковой высоты. Сертификат создаётся заново для фактического порядка. Генератор не выполняет непроверенное слепое перемешивание. «Повторить раскладку» вообще не регенерирует её: берёт **сохранённый точный исходный порядок всех 108 ID**. «Новая раскладка» создаёт другой экземпляр выбранного режима. Четыре человеческих названия доступны без seed и диагностических параметров; игрок сразу получает все k обязательных ячеек бесплатно. Дополнительных ячеек, рекламы и покупок нет.

Отдельно доказан выбор **размера пачки** в R_min=1: у той же пары колонок перенос одной фишки сохраняет WIN, перенос двух даёт LOSE из **185 состояний / 894 переходов**. Реальный браузер выбирает пачки 1/2, получает доказанный тупик, восстанавливает родителя одним Undo и выполняет победную альтернативу.

Поиск свидетелей целевой, а не случайная выборка человеческих партий. Из этих чисел нельзя выводить частоту проигрыша или статистически ранжировать человеческую сложность. Простое конструктивное семейство было проверено на обратимость локальных альтернатив; это помогло обнаружить, что множество циклических ходов само по себе не даёт риска. Более смешанные скрытые хвосты внесли настоящие опасные ветви.

**Открытой информации не всегда достаточно.** Два настоящих члена обычного пула, `perturbed-r1-11` и `perturbed-r1-0`, дают **14 одинаковых наблюдений**: старт и общий префикс из 13 действий. Совпадают виды открытых фишек, маски закрытых, высоты и резерв. Один и тот же ход даёт в A проверенный LOSE, в B — проверенный WIN. Оба корня и оба родителя решаемы, оба имеют R_min=1. В варианте с выбором размера пачки совпадают 15 наблюдений. Копии ID не входят в человеческую видимую информацию; скрытые kind/ID не попадают в обычный DOM.

[Пара двух реальных членов пула](../../tests/fixtures/v05/pool-hidden-pair.json). Кроме того, для каждого класса проверены пары допустимых скрытых дополнений с 14/23/44/87 совпадающими наблюдениями и разным исходом одного хода. Это доказательства существования неоднозначности в указанном пространстве состояний, а не оценка её частоты. Безопасность скрытого выбора заранее игроку не обещается.

## Сохранение и правильное решение

В `game/session.ts` сохраняются текущая партия, состояние добровольной сдачи, исходная доска, ID/seed, алгоритм и его версия, полный положительный trace, нижний сертификат и SHA-256. Перед использованием после F5 и **перед каждым показом** повторно проверяются целостность, барьер и действительная победа через production engine. Повреждённый trace, даже с пересчитанным SHA, не проходит проверку. При повреждении решения текущая корректная партия сохраняется; кнопка replay отключается с понятной причиной. Невозможно молча показать другую раскладку вместо повреждённой исходной.

При доказанном тупике сохраняется и замкнутое доказательство; после F5 оно проверяется заново. Один записанный флаг LOSE без корректного доказательства не принимается. Фоновый worker ограничен 8 000 состояниями / 350 мс; задержка, отсутствие worker или лимит дают UNKNOWN и не открывают диалог проигрыша. Наличие циклов не выдаётся за возможность победить.

После сдачи или доказанного тупика доступны повтор, новая раскладка и показ решения. При доказанном тупике доступен Undo, если есть история. Сдача не засчитывает победу.

`replay/player.ts` — отдельный проигрыватель: создаёт копию исходной доски и кадры **реальными действиями движка**, без присваивания готового финала. К игровой партии, localStorage, рекордам и начислению побед доступа не имеет. Показывает полупрозрачную выбранную пачку, плавный перенос, переворот нового «?», освобождение/заполнение колонок и настоящую конечную победу. Play/Pause, шаги, 1×/2×/4×, Restart и Close работают с мышью, touch и клавиатурой. Стрелки — шаги, пробел — Play/Pause, Home — сначала, Escape — закрыть.

Пауза останавливает таймеры и приводит начатое атомарное действие к уже применённому кадру; она не хранит промежуточную долю визуального переноса. Закрытие отменяет все анимации и таймеры. При reduced-motion движения не анимируются, последовательность и шаги сохраняются. Управление остаётся постоянными DOM-узлами между кадрами, чтобы быстрая перерисовка не теряла клик по Pause. Шаг назад берёт проверенный предыдущий кадр и не расходует игровой Undo. Достижение конца replay не меняет победы, очки или сохранение пользователя.

- Браузер для каждого класса: настоящий плохой ход → доказанный тупик → один Undo → настоящая победная альтернатива. Затем повтор точной доски, добровольная сдача, F5, replay до настоящей победы. - Самостоятельный браузерный игрок получает только маскированную проекцию, без seed, ID скрытых фишек или сертификата. В других двух фиксированных примерах лимит 200 действий: в классе 2 последующая проверка доказывает LOSE, в классе 4 победа не установлена. Это конкретные ограниченные прогоны, а не человеческая вероятность успеха.

Скрипты `tests/browser-v05-*.js` используют Playwright CLI и настоящие клики/тапы; победа не инъецируется. Сценарии с известными сертификатами отделены от самостоятельного выбора по открытой информации. Проверки опубликованного сайта повторяются после push, а файлы сравниваются с локальным `dist`.

## Воспроизведение и ограничения

`npm ci`, `npm test`, `npm run certify:v05`, `npm run build`; разработка: `npm run dev:v05`. Публикация остаётся автоматической после push в main. После деплоя: `npm run verify:pages`, `npm run verify:pages:v04`, `npm run verify:pages:v05`. Браузерные результаты и скриншоты приёмки лежат локально в `output/playwright/*v05*`.

Обычный URL: `/secret-sort-dev/v05/`. Диагностика только по явному `?qa=1`; для воспроизведения сертификата можно добавить `&mode=1&seed=perturbed-r1-11`. Объект `__secretSortV05` предоставляет только копии для чтения; методов подмены игры нет.

R_min — математическая потребность в резерве, не оценка удовольствия или стратегической сложности человека. Набор разнообразнее четырёх полей, но остаётся семейством с барьером и зависимостями; победные пути не оптимизированы и содержат много одиночных переносов для открытия закрытых слоёв. Скрытая информация может определять исход до того, как игрок узнает её. UNKNOWN не означает ни WIN, ни LOSE. История игрового Undo по-прежнему ограничена 80 действиями. Физический смартфон, человеческий плейтест и производительность слабого телефона не проверены; viewport и touch эмулированы в настоящем браузере на компьютере. Изоляция копий исходников необходима для сохранения v0.3/v0.4; стек и арт не менялись. Рекламы, валют, покупок и дополнительных резервных ячеек нет.
