# «Секретная сортировка» v0.4 — эксперимент

Стабильная v0.3: https://artem917.github.io/secret-sort-dev/
Эксперимент v0.4: https://artem917.github.io/secret-sort-dev/v04/
Сохранённая база: `05ad3b7d8127696eba8d7a92e165ec7ec8082d61`.

## Что опубликовано

Vite + TypeScript, тот же движок переносов, 108 фишек / 9×12, резерв 4, автоматическое раскрытие и одна атомарная отмена. CSS и исходник движка эксперимента проверяются на равенство стабильной версии. Обычный старт полностью перемешивает все 108 фишек алгоритмом Fisher–Yates; готовых шаблонов и подмены тренировкой нет. Допускаются только партии с победным сертификатом, повторно исполненным настоящим движком. Поиск вынесен в Web Worker.

Seed остаётся внутренним детерминированным идентификатором; из меню, игрового поля, диалогов и рекордов убран. «Повторить раскладку» воспроизводит тот же старт, «Новая раскладка» делает другой shuffle. Выбор пачки больше не подсвечивает все легальные цели. Подсказка по запросу показывает только легальный ход и не обещает его безопасность. Закрытые фишки не отдают вид/ID в DOM и в маскированную проекцию тестового игрока.

## Точный смысл WIN / LOSE / UNKNOWN

Оракул исследует **прямые ходы без Undo**. Немедленная отмена в настоящей игре сохраняется: ошибочный ход можно отменить. Поэтому LOSE ниже означает отсутствие победного продолжения без возврата назад, а не необратимый проигрыш пользователя.

| Исход | Необходимое доказательство |
|---|---|
| WIN | Последовательность действий, исполненная `applyAction` до настоящей победы |
| LOSE | Весь достижимый граф исчерпан, побед нет, фронтир пуст; проверяемый замкнутый сертификат |
| UNKNOWN | Лимит состояний/времени; никаких утверждений о нерешаемости |

Учитываются все размеры пачек, частичные переносы, резерв, возвраты, перестановки и циклы. Эвристика только упорядочивает поиск. Одинаковые по виду ID, перестановки колонок и слотов резерва — точные симметрии правил. Бесплатное открытие доступных верхних фишек выполняется заранее: оно только добавляет ходы и не запрещает ни одного уже доступного. Эти преобразования сохраняют существование прямого решения. Встреченный цикл сам по себе не является доказательством LOSE.

`verifyClosedProof` проверяет каждый исходящий переход замкнутого множества. Дополнительно тест независимо перечисляет все переходы 11-состоянийного тупика через **настоящий движок**, а не через функцию переходов solver. Повреждённые сертификаты отвергаются.

## Полный shuffle и допуск

Замороженная до просмотра результатов когорта `shuffle-0..31`:

| Бюджет на раскладку | WIN | LOSE | UNKNOWN |
|---|---:|---:|---:|
| 20 000 состояний / 1 с | 31 | 0 | 1 |
| 80 000 состояний / 8 с — допуск v0.4 | 32 | 0 | 0 |

Первый UNKNOWN — `shuffle-11`; увеличение лимита нашло решение, что прямо демонстрирует разницу UNKNOWN и LOSE. Все победные сертификаты проверены движком с контролем 108 ID после каждого действия. [Полные результаты](experiment.json).

После одного незалогированного случайного отказа в браузере отдельно проверена диагностическая когорта `shuffle-32..63`: **31 WIN / 0 LOSE / 1 UNKNOWN** при бюджете допуска. `shuffle-49` достигает 80 000 состояний; реальный браузер проверяет правильный отказ в допуске. [Данные](additional-cohort.json).

Для каждого seed существует ровно один shuffle. При UNKNOWN программа не заменяет его другим под тем же идентификатором и не выдаёт непроверенную партию. Показывается сообщение, что решение не подтверждено; предыдущая партия сохраняется. Пользователь может запросить новую раскладку. В потоке браузерного приёма есть watchdog 12 с; сбой worker также не превращается в LOSE. Отбор WIN делает распределение допущенных партий условным, а не равномерным по всем перестановкам. PRNG с 32-битным состоянием детерминированный, не криптографический.

## Настоящие опасные развилки

Есть два воспроизводимых свидетеля в настоящих full-shuffle партиях. Номера колонок в таблице — **1..10**, JSON использует **0..9**.

| Партия / достижимый родитель | Опасный легальный ход | Доказательство LOSE | Победная альтернатива |
|---|---|---|---|
| `shuffle-0`, после 25 переносов | Колонка 3 → 1, **группа 2** | Замкнутый граф **4 состояния** | Сертификат ещё 92 переносов |
| `shuffle-12`, после 23 переносов | Колонка 7 → 8, **1 фишка** | Замкнутый граф **11 состояний / 28 переходов** | Сертификат ещё 99 переносов |

Каждый родитель достигнут из исходной скрытой раскладки легальным префиксом. Его WIN подтверждён продолжением; проигрышный ребёнок не объявлен таковым по таймауту. В браузере оба префикса, плохой ход, **один Undo**, точное восстановление родителя и победная альтернатива исполнены настоящими кликами/касаниями. Это сценарии интеграционной проверки по сертификатам, отдельно от игры по открытой информации.

Свидетели: [групповой риск](../../tests/fixtures/v04/group-risk-witness.json), [одиночный риск](../../tests/fixtures/v04/shuffle-risk-witness.json). Проверяются автоматически в `tests/v04.test.mjs`.

## Сравнение v0.3 / v0.4

Одинаковые восемь seed `shuffle-0..7`, по пять точек на проверенном победном пути: открытый старт, после 25/50/75 переносов, за пять переносов до победы. Все 80 родителей заведомо WIN по оставшемуся сертификату. Дети сгруппированы по точным симметриям. Проверены все, если их ≤16; иначе первые 16 по заранее заданному FNV-порядку. Бюджет ребёнка: 1 000 состояний / 100 мс.

| Измерение | v0.3 reverse-packets | v0.4 full shuffle |
|---|---:|---:|
| Родительские позиции | 40 | 40 |
| Проверенные различные дети | 624 | 535 |
| WIN | 270 | 208 |
| **Доказанные LOSE** | **0** | **1** |
| UNKNOWN | 354 | 326 |
| Не проверены из-за ограничения выборки | 334 | 175 |
| Родители с доказанной опасной развилкой | 0 | 1 |

478 найденных выигрышных продолжений повторно исполнены движком. Единственный LOSE в этой выборке — групповой свидетель `shuffle-0`. Одиночный свидетель `shuffle-12` найден отдельным поиском и в таблицу не добавлен. **Ноль доказанных LOSE у v0.3 не означает их отсутствия**. UNKNOWN и непроверенные дети не считаются безопасными. Выборка мала и проходит по путям solver: общего статистического ранжирования сложности или частоты риска из неё не следует. Число легальных переносов не используется как замена опасным развилкам.

## Честность по открытой информации

Обнаружено существенное ограничение, а не доказана общая справедливость. [Пара скрытых дополнений](../../tests/fixtures/v04/reachable-hidden-risk-pair.json) имеет одинаковую видимую историю из 33 действий, одинаковые открытые фишки/ID, размеры колонок и резерв. Оба родителя WIN. Один и тот же видимый легальный ход приводит:

- в дополнении A — к доказанному LOSE из 11 состояний;
- в дополнении B — к WIN с проверенным продолжением.

A получено из настоящего `shuffle-12`; B — допустимый старт с обменом двух никогда не наблюдавшихся закрытых фишек. Для B **не заявлен конкретный PRNG seed**. Начальные высоты, 108 ID и 9×12 сохранены. Автотест сравнивает все 34 видимых наблюдения от старта до родителя, а не только последний кадр.

Следовательно, открытой информации не всегда достаточно для гарантированно безопасного решения: часть риска зависит от скрытого содержимого. Undo даёт возможность восстановления, но не превращает неизвестную фишку в известную до выбора. Это отмечено в правилах эксперимента. Нельзя заявлять, что v0.4 уже стала исключительно головоломкой на логическое предвидение.

Дополнительное самоиспытание всех 32 seed без скрытых видов, seed и сертификатов на входе политик ([данные](visible-play.json)):

| Политика | Реальные победы | Остальные исходы |
|---|---:|---|
| Видимая жадная, лимит 400 действий | 7/32 | 18 лимитов, 7 остановок перебора |
| Видимый поиск с настоящим Undo, лимит 2 000 действий | 4/32 | 28 лимитов |

Это результаты конкретных ограниченных ботов, не вероятность победы человека. Лимит бота также не означает LOSE. Финальные позиции отдельно классифицированы трёхзначным оракулом в данных.

## Проверки и браузер

`npm test`: **69/69 PASS**, включая прежние 58 тестов. Среди прежних проверок — 2 000 полных решений v0.3 / 252 906 действий. Новые проверки покрывают три исхода solver, 32 допуска full shuffle, замкнутые LOSE, независимый обход, групповую развилку, скрытую пару, изоляцию сохранений и атомарный Undo.

Браузерные скрипты работают через Playwright CLI с настоящими кликами/тапами; состояние победы не подставляется:

- `browser-v04-geometry.js`: 320×568, 360×740, 390×844, 412×915, 768×1024, 1366×768; по пять состояний, **124 ячейки** плюс основные кнопки, bounding boxes, clipping, hit-test центров, нулевая прокрутка поля.
- `browser-v04-scenarios.js`: два опасных хода, восстановление одним Undo и победные продолжения; F5, автораскрытие, повтор/новая раскладка, рекорды, изоляция v0.3, отсутствие seed и постоянной подсветки. По 22 проверки в каждом сценарии, ноль ошибок браузера/ресурсов в локальном прогоне.
- `browser-v04-visible.js`: самостоятельный выбор только по маскированной проекции. Фиксированные примеры `shuffle-0`, `shuffle-1`, `shuffle-12`, лимит 200 действий. **`shuffle-1` выигран за 123 действия / 113 переносов / 66 групп / 11 входов в резерв, 6 610 очков** на 320×568. Другие два — лимит 200, а не заявление о проигрыше. Выбор примеров включает два документированных риск-корня и один пример победы видимой политики из полной когорты; это не случайная оценка успеха.
- `browser-v04-edgecases.js`: настоящий UNKNOWN worker на `shuffle-49`, отсутствие фиктивной партии/Continue, выключенный QA в обычном URL, требуемые названия кнопок.

## Изоляция и воспроизведение

Корневые `src`, `public`, `index.html`, `vite.config.ts` v0.3 не менялись. Две независимые сборки предотвращают изменение старых чанков. `scripts/stable-v03-manifest.json` фиксирует SHA256 всех **14 опубликованных файлов v0.3**; `npm run build` обязан подтвердить их равенство. v0.4 собирается в `dist/v04` с base `/secret-sort-dev/v04/`. Ключи localStorage начинаются с `secret-sort:v04:` и не читают/пишут старые ключи. В браузерном сценарии старое сохранение сначала создаётся через UI v0.3 и сравнивается побайтово после игры в v0.4.

Команды: `npm ci`, `npm test`, `npm run build`, `npm run experiment:v04`, `node scripts/visible-play-v04.mjs`. Для локальной игры: `npm run dev:v04`. GitHub Actions после push в main запускает тесты, обе сборки и публикацию `dist` в GitHub Pages. После деплоя: `npm run verify:pages` и `npm run verify:pages:v04` сравнивают HTTP-ответы с локальными файлами, включая worker.

QA только по `?qa=1`; внутренний воспроизводимый тестовый URL может содержать `&seed=shuffle-12`. Объект `__secretSortV04` доступен только для чтения и не имеет методов изменения игры. Обычный UI не предлагает технического ввода seed.

## Ограничения

Это эксперимент: существование решения на старте не гарантирует ни безопасного следующего хода, ни распознаваемости риска по открытой информации. Оракул не доказывает нерешаемость по лимиту. Есть отказ в допуске некоторых раскладок; нужны дальнейшие измерения частоты и производительности на настоящих телефонах. Браузер проверен с мобильными viewport и touch-эмуляцией на компьютере, физический смартфон и человеческий плейтест не проводились. Данные ботов не доказывают удовольствие или удержание. Undo хранит прежние 80 действий и прежнюю стоимость. Ради побайтового сохранения стабильной сборки код v0.4 изолирован копией движка; тест равенства защищает от непреднамеренного расхождения. Реклама, уровни и валюты не добавлены.
